# 轻量项目看板

为小团队建设可长期使用的本地项目协作产品，逐步覆盖项目与任务、看板状态、负责人和标签、评论与变更历史、筛选检索、简单工作量统计以及数据导入导出。

计划采用：Python 3 标准库 / sqlite3 / argparse。

## 当前功能

项目与任务的创建、任务状态移动、项目内任务查询。数据保存在本地 SQLite 文件中，无需网络或第三方服务。

## 用法

```bash
python -m kanban --db <数据库路径> project-create <项目名称>
python -m kanban --db <数据库路径> project-list [--query <关键词>]
python -m kanban --db <数据库路径> project-rename <项目标识> <新名称> [--from <预期原名称>]
python -m kanban --db <数据库路径> task-create <项目标识> <任务标题>
python -m kanban --db <数据库路径> task-move <任务标识> <todo|doing|done> [--from <todo|doing|done>]
python -m kanban --db <数据库路径> task-rename <任务标识> <新标题> [--from <预期原标题>]
python -m kanban --db <数据库路径> task-show <任务标识>
python -m kanban --db <数据库路径> task-transfer <任务标识> <目标项目标识>
python -m kanban --db <数据库路径> task-list <项目标识> [--status <todo|doing|done>] [--query <关键词>]
python -m kanban --db <数据库路径> project-stats <项目标识> [--status <todo|doing|done>]... [--query <关键词>]
```

- 数据库文件不存在时，首次成功操作会自动创建；多个进程使用同一路径可共享数据。
- 项目与任务使用稳定的正整数标识，任务标识在同一数据库内跨项目唯一。
- 名称与标题保存前去除首尾空白，允许重名；新任务初始状态为 `todo`。
- `project-list` 返回数据库中全部项目（含尚无任务的项目），每个项目只含 `id` 与 `name`，按 `id` 数值升序；同名项目各自保留，名称按已保存的值原样返回；查询不改动任何数据。
- `project-list` 可附加 `--query 关键词`，只返回项目名称包含该关键词的项目：关键词先去除首尾空白（内部空白保留），再按大小写敏感的连续子串匹配，不分词、不归一化，中文、`%`、`_`、引号均为普通字符，且只匹配项目名称、不匹配任务标题（项目名称不含关键词时，即使其任务标题命中也不出现）；同名项目各自保留，尚无任务的项目同样参与匹配，没有项目或没有命中时返回空数组。省略 `--query` 时返回全部项目。
- `project-rename` 按项目标识修改名称，只改该项目的名称，项目标识与该项目下全部任务的标识、标题、状态和所属项目均保持不变，也不会创建项目或合并同名项目；其他项目不受影响。项目标识允许前导零并按数值判断。新名称沿用创建项目的规则：去除首尾空白（内部空白、大小写、中文、`%`、`_` 与引号等原样保留），允许改成其他项目的名称。处理后与当前名称相同时也算成功，返回当前项目且不新增记录。返回的对象只含 `id`、`name`，分别为原标识与保存后的名称。
- `project-rename` 可附加 `--from <预期原名称>`，在改名前确认项目已保存的名称仍符合预期：预期原名称与新名称都先去除首尾空白（内部空白、大小写、中文、`%`、`_` 与引号等原样保留），仅当处理后的预期原名称与项目已保存的名称逐字相等（精确匹配，不分词、不归一化、不做大小写或空白折叠，也不做其他模糊匹配）时才保存新名称；预期不匹配时拒绝改名，退出码为 2，标准输出为空，标准错误同时说明已保存的当前名称与处理后的预期原名称，不修改目标项目名称、其下任务的任何字段或其他项目数据。即使新名称处理后与当前名称相同，只要预期不匹配也按此规则拒绝；预期匹配且新名称与当前相同时则成功返回原项目，不新增记录。预期原名称去除首尾空白后为空属于参数错误（退出码 2）。`--from` 省略时保持上述不检查原名称、直接改名的现有规则（仍允许重名与同名称提交）。
- `task-rename` 按跨项目唯一的任务标识修改标题，只改该任务的标题，标识、所属项目与当前状态保持不变；任务标识允许前导零并按数值判断。新标题沿用创建任务的规则：去除首尾空白（内部空白、大小写、中文、`%`、`_` 与引号等原样保留），允许与其他任务重名。处理后与原标题相同时也算成功，返回当前任务且不新增任务。返回的对象只含 `id`、`project_id`、`title`、`status`。
- `task-rename` 可附加 `--from <预期原标题>`，在改名前确认任务已保存的标题仍符合预期：预期原标题与新标题都先去除首尾空白（内部空白、大小写、中文、`%`、`_` 与引号等原样保留），仅当处理后的预期原标题与任务已保存的标题逐字相等（精确匹配，不分词、不归一化、不做大小写或空白折叠，也不做其他模糊匹配）时才保存新标题；预期不匹配时拒绝改名，退出码为 2，标准输出为空，标准错误同时说明已保存的当前标题与处理后的预期原标题，不新增任务、不改变目标任务或其他任务的任何数据。即使新标题处理后与当前标题相同，只要预期不匹配也按此规则拒绝；预期匹配且新标题与当前相同时则成功返回原任务，不新增记录。预期原标题去除首尾空白后为空属于参数错误（退出码 2）。`--from` 省略时保持上述不检查原标题、直接改名的现有规则（仍允许重名与同标题提交）。
- `task-move` 按跨项目唯一的任务标识修改状态，只改该任务的状态，标识、所属项目与标题保持不变，同标题任务按各自标识区分，其他任务不受影响；任务标识允许前导零并按数值判断（`0001` 与 `1` 等价）。省略 `--from` 时，`todo`、`doing`、`done` 三种合法状态之间可直接转换，目标状态与当前状态相同时也算成功，返回当前任务且不新增记录。返回的对象只含 `id`、`project_id`、`title`、`status`。
- `task-move` 可附加 `--from <todo|doing|done>` 指定本次移动预期的当前状态：仅当任务已保存的状态与 `--from` 完全相同（按原样拼写精确匹配）时，才把状态设置为目标状态；来源状态合法但与当前值不同时拒绝移动，退出码为 2，标准错误说明当前状态与预期状态，不创建任务、不改变目标任务或其他任务的任何数据。即使目标状态与当前状态相同，只要来源状态不匹配也按此规则拒绝；当前状态与预期相符且目标与当前相同时则成功返回原任务，不新增记录。`--from` 与目标状态都只接受三种状态的原样拼写，大小写变化、首尾空白、空字符串或未知值均为非法状态。`--from` 省略时保持上述不加来源校验的现有移动规则。
- `task-show` 按跨项目唯一的任务标识读取单条任务，无需先知道所属项目。返回的对象只含 `id`、`project_id`、`title`、`status`：标题按数据库中保存的值原样返回，状态为当前值，同标题任务按各自标识区分。查询为只读操作，不改动任何数据，重复查询结果一致。任务标识沿用正整数规则：允许前导零并按数值判断（`0001` 与 `1` 等价）；标识无效、越界或该标识在当前数据库中不存在时退出码为 2。
- `task-transfer` 按跨项目唯一的任务标识把单条任务转移到已有项目，无需输入来源项目：只修改该任务的所属项目，任务标识、标题、状态原样保留，其他任务与项目名称不变，不复制任务、不新增记录、不创建项目。任务标识与目标项目标识都沿用正整数规则：允许前导零并按数值判断（`0001` 与 `1` 等价）。目标项目就是任务当前所属项目时仍成功返回原任务；目标项目为空或已有同标题任务时也允许转移，同名项目始终按标识区分。返回与 `task-show` 一致的单个任务对象（`id`、`project_id`、`title`、`status`），后续命令读取同一数据库即可看到新的归属，`project-stats` 按新归属统计。
- `task-list` 可附加 `--status todo|doing|done` 只返回该项目中匹配状态的任务，按原样拼写精确匹配；省略时返回项目全部任务。
- `task-list` 可附加 `--query 关键词`，只返回标题包含该关键词的任务：关键词先去除首尾空白（内部空白保留），再按大小写敏感的连续子串匹配，不分词、不归一化，`%`、`_`、引号均为普通字符，且只匹配标题；可与 `--status` 同时使用，两个条件取交集。
- `project-stats` 返回单个对象，只含 `project_id`、`total`、`todo`、`doing`、`done`：`total` 为该项目全部任务数，其余三者为各状态当前数量（同标题任务各计一次，其他项目任务不计入），三者之和等于 `total`；空项目四个数量均为 0。统计反映当前已保存的状态，不累计移动次数，查询不改动任何数据，重复查询结果一致。
- `project-stats` 可附加 `--query 关键词`，统计范围缩小为标题包含该关键词的任务，匹配规则与 `task-list --query` 完全一致：关键词先去除首尾空白（内部空白保留），再按大小写敏感的连续子串匹配，不分词、不归一化，中文、`%`、`_`、引号均为普通字符，且只匹配任务标题、不匹配项目名称；`total` 与 `todo`、`doing`、`done` 均只统计命中的任务，三者之和等于 `total`。关键词没有命中或项目没有任务时仍成功返回，四个数量均为 0。省略 `--query` 时统计范围保持为项目全部任务。
- `project-stats` 可附加 `--status todo|doing|done`，统计范围缩小为匹配状态的任务，按原样拼写精确匹配（大小写变化或带首尾空白均为非法状态）；`--status` 可在同一次调用中重复传入，每次接收一个状态，多个状态取并集，状态顺序与重复值不影响结果，同一任务只计一次，全部三种状态等同于省略状态筛选；每次出现的值都校验，任一非法即拒绝整次查询。`total` 等于命中任务数，各状态数量只统计命中任务，未选择状态的数量为 0，三者之和等于 `total`。可与 `--query` 同时使用，两类条件取交集；筛选无命中或空项目仍成功返回，四个数量均为 0。只传一个状态或省略 `--status` 时统计范围与之前一致（省略时保持为项目全部任务）。
- 成功时退出码为 0，标准输出为单个 JSON 值（对象或数组），标准错误为空。
- 参数缺失、名称/标题/关键词为空、标识非正整数或超出 SQLite 整数支持范围（1..9223372036854775807）、项目或任务不存在、状态非法，或 `project-rename --from` 的预期原名称与项目已保存名称、`task-rename --from` 的预期原标题与任务已保存标题逐字不相等时，退出码为 2，标准错误说明原因，数据不变。标识允许前导零并按数值判断边界（`0001` 与 `1` 等价，前导零不影响是否越界）。
- 数据库无法打开或文件不可用时，退出码为 1，标准错误说明存储失败。
